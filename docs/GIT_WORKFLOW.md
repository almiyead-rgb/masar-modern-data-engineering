The eight labs build the same final project.</p></td><td width="50%" dir="rtl" lang="ar" align="right" valign="top"><h1>احفظ مشروعك باستخدام Git</h1><p>استخدم مستودعًا واحدًا داخل حسابك في GitHub للأيام الخمسة. تبني اللابات الثمانية المشروع النهائي نفسه.</p></td></tr></table>

<table dir="ltr" width="100%"><tr><td width="50%" dir="ltr" lang="en" align="left" valign="top"><h2>1. Create your own copy</h2><p>Open <a href="https://github.com/almiyead-rgb/masar-modern-data-engineering">the course repository</a>, select <strong>Fork</strong>, choose your personal account and create the fork. On your fork, select <strong>Code → HTTPS</strong> and copy its clone URL. Clone that URL on your computer; do not use the instructor’s repository as your push destination. Follow <a href="SETUP.md">the environment setup</a> next.</p><p>A fork of this public course is public. Use only the supplied synthetic data and learning notes that you are comfortable sharing. Do not add personal records, passwords or tokens.</p></td><td width="50%" dir="rtl" lang="ar" align="right" valign="top"><h2>1. أنشئ نسختك الخاصة</h2><p>افتح <a href="https://github.com/almiyead-rgb/masar-modern-data-engineering">مستودع الدورة</a>، واختر <strong>Fork</strong> ثم حسابك الشخصي وأنشئ النسخة. داخل نسختك اختر <strong>Code → HTTPS</strong> وانسخ رابط الاستنساخ إلى جهازك. يجب أن يكون مقصد رفع عملك مستودعك، وليس مستودع المدربة. تابع بعد ذلك <a href="SETUP.md">إعداد البيئة</a>.</p><p>نسخة Fork من هذه الدورة العامة تكون عامة أيضًا. استخدم البيانات الاصطناعية المرفقة وملاحظات التعلم المناسبة للمشاركة فقط. لا تضف سجلات شخصية أو كلمات مرور أو رموز وصول.</p></td></tr></table>

<table dir="ltr" width="100%"><tr><td width="50%" dir="ltr" lang="en" align="left" valign="top"><h2>2. Check the destination and start a branch</h2><p>Run the commands below from your local repository folder. The <code>origin</code> address must contain your GitHub username. Create <code>develop</code> once. In later sessions, use <code>git switch develop</code> instead of creating the branch again.</p></td><td width="50%" dir="rtl" lang="ar" align="right" valign="top"><h2>2. تحقق من وجهة الرفع وابدأ فرعًا</h2><p>نفّذ الأوامر التالية من مجلد مستودعك على الجهاز. يجب أن يحتوي عنوان <code>origin</code> على اسم حسابك في GitHub. أنشئ فرع <code>develop</code> مرة واحدة؛ وفي الجلسات التالية استخدم <code>git switch develop</code> للانتقال إليه.</p></td></tr></table>

```bash
git remote -v
git switch -c develop
```

<table dir="ltr" width="100%"><tr><td width="50%" dir="ltr" lang="en" align="left" valign="top"><h2>3. Save a completed learning step</h2><p>Save the notebook with your actual outputs and write your lab notes before staging files. The example below is for Day 1 and assumes you have created <code>LAB01_NOTES.md</code> and <code>LAB02_NOTES.md</code>. Use <a href="../templates/LAB_NOTES.md">the note template</a>. For other days, select only the files you actually changed. Keep code, filenames and commit messages in English.</p></td><td width="50%" dir="rtl" lang="ar" align="right" valign="top"><h2>3. احفظ مرحلة مكتملة من تعلمك</h2><p>احفظ الدفتر بمخرجات تشغيلك واكتب ملاحظات اللاب قبل تحديد الملفات للحفظ. المثال التالي لليوم الأول، ويفترض أنك أنشأت <code>LAB01_NOTES.md</code> و<code>LAB02_NOTES.md</code>. استخدم <a href="../templates/LAB_NOTES.md">قالب الملاحظات</a>. في بقية الأيام حدد الملفات التي عدّلتها فعلًا فقط. استخدم الإنجليزية للكود وأسماء الملفات ورسائل التعديل.</p></td></tr></table>

```bash
git status
git diff
git add day01/STUDENT.ipynb LAB01_NOTES.md LAB02_NOTES.md
git diff --staged
git commit -m "Complete Day 1 Bronze and scan experiments"
git push -u origin develop
```

<table dir="ltr" width="100%"><tr><td width="50%" dir="ltr" lang="en" align="left" valign="top"><h2>4. Verify the uploaded work</h2><p>Open your fork on GitHub and select <code>develop</code>. Check that your latest commit, notebook outputs and notes are visible. A local commit alone does not upload files. Authenticate through your configured GitHub sign-in method when prompted; never paste a token into a notebook or a repository file.</p><p>If <code>origin</code> points to the course repository, copy the HTTPS URL of your own fork, then use <code>git remote set-url origin YOUR_FORK_URL</code>, replacing <code>YOUR_FORK_URL</code> with that URL. Recheck with <code>git remote -v</code>. Do not force-push to repair an access error.</p></td><td width="50%" dir="rtl" lang="ar" align="right" valign="top"><h2>4. تحقق من العمل المرفوع</h2><p>افتح مستودعك في GitHub واختر <code>develop</code>. تحقق من ظهور آخر تعديل ومخرجات الدفتر والملاحظات. أمر الحفظ المحلي وحده لا يرفع الملفات. سجّل الدخول بالطريقة التي أعددتها لـGitHub عند طلب المصادقة؛ لا تضع رمز وصول داخل دفتر أو ملف في المستودع.</p><p>إذا كان <code>origin</code> يشير إلى مستودع الدورة، فانسخ رابط HTTPS لنسختك ثم استخدم <code>git remote set-url origin YOUR_FORK_URL</code> بعد استبدال <code>YOUR_FORK_URL</code> برابطك. تحقق مجددًا بأمر <code>git remote -v</code>. لا تستخدم الدفع القسري لمعالجة خطأ الصلاحيات.</p></td></tr></table>

<table dir="ltr" width="100%"><tr><td width="50%" dir="ltr" lang="en" align="left" valign="top"><h2>5. Submit the correct branch and commit</h2><p>Follow <a href="../project/SUBMISSION.md">the submission guide</a>. Include the URL of the branch containing your completed work and its final commit ID. Use <code>git rev-parse HEAD</code> to obtain the ID. When your work is on <code>develop</code>, share that branch’s URL rather than a link that opens an unchanged <code>main</code>. No pull request to the course repository is required.</p><p>Keep <code>outputs/</code>, handoff ZIPs, virtual environments, JAR files, caches and credentials out of ordinary commits. Retain the generated archive through the organizer’s approved channel. Record small observed results inside your notebooks.</p></td><td width="50%" dir="rtl" lang="ar" align="right" valign="top"><h2>5. سلّم الفرع والتعديل الصحيحين</h2><p>اتبع <a href="../project/SUBMISSION.md">دليل التسليم</a>. أدرج رابط الفرع الذي يحتوي على عملك المكتمل ومعرف تعديله النهائي. استخرج المعرف بأمر <code>git rev-parse HEAD</code>. عندما يكون عملك داخل <code>develop</code>، شارك رابط هذا الفرع بدل رابط يفتح <code>main</code> دون تعديلاتك. لا يُطلب إرسال Pull Request إلى مستودع الدورة.</p><p>استبعد <code>outputs/</code> وملفات ZIP للانتقال والبيئات الافتراضية وملفات JAR وذاكرة الحزم وبيانات الدخول من التعديلات الاعتيادية. احتفظ بالأرشيف المولد عبر القناة التي تعتمدها الجهة، وسجل النتائج الفعلية الصغيرة داخل دفاترك.</p></td></tr></table>
